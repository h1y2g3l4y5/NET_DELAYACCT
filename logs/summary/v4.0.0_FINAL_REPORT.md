## 二、关键设计决策

### 2.1 min/max 统计

- **min_ns 初始化为 U64_MAX**：确保第一个样本总是更小，避免初始化为 0 导致 min 永远为 0 的 bug
- **max_ns 保持 0 初始化**：第一个样本总是更大
- **用户态归一化**：count==0 时，将内核报告的 min=U64_MAX/max=0 显示为 0
- **O(1) 复杂度**：每次 RX/TX end 仅增加两次比较，性能开销可忽略

### 2.2 RESET 语义

- **per-socket 原子性**：`net_delayacct_reset()` 与 `net_delayacct_rx_end()`/`net_delayacct_tx_end()` 都持有同一个 `n->lock` spinlock
- **不保证全局原子快照**：RESET 遍历所有进程的 socket 需要一定时间，期间已清零的 socket 仍可能有新包到达并累加
- **文档化对齐内核惯例**：与 `/proc/net/snmp`、`ss`/`netstat` 的多对象统计遍历语义一致
- **满足性能测试需求**："reset then observe for an interval" 工作流的核心是清零后新到达流量的统计，而非清零时刻的全局快照

### 2.3 64 位溢出检测

- **检查在 spinlock 内**：避免检查和累加之间的竞态
- **pr_warn_once 而非 pr_warn**：避免高吞吐场景下日志洪泛
- **溢出后继续累加（回绕）**：不丢弃统计，仅告警让运维知晓

## 六、系统性教训

### 6.1 同步 patch 时必须全量检查

v4.0.0 修复中，Worker 初次同步 0005/0007 时遗漏了 0006（内部头文件新增 min/max 初始化）。后续用 `grep -c` 全量检查所有 patch 文件才避免 CI 回归。

**建议固化为流程**：
- 修改内核源文件后，必须同步所有相关 patch
- 使用 `grep -c` 检查所有 patch 文件中新增/修改的符号
- patch body 与源文件必须通过 diff 验证 MATCH

### 6.2 统计语义需要在文档中显式说明

RESET 命令的"全局原子快照"预期是用户容易误解的点。应在设计初期就在 UAPI 和内部头文件中明确语义，避免后期作为 Review 议题补充。

### 6.3 头文件注释是 API 契约的一部分

min/max 的 `U64_MAX` 初始化语义、RESET 的非全局快照语义、溢出后的回绕行为，都应该在头文件注释中清晰记录。这不仅是文档，也是用户态开发者正确理解和使用 ABI 的依据。
