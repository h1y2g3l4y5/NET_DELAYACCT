## 二、关键设计决策

### 2.1 Generic Netlink dumpit 重构（ISSUE-3）

- **标准 dump 协议**: `GET_BY_PID` 改为 `.start/.dumpit/.done` 三件套，由 Generic Netlink 框架自动处理 `NLM_F_MULTI` 分片和 `NLMSG_DONE`
- **`cb->ctx` 内联数组**: 内核 6.6 中 `struct netlink_callback` 的 `ctx` 是 `u8 ctx[48]`，直接 cast 40 字节的 `net_delayacct_dump_ctx`，不需要 kzalloc/kfree
- **GET_BY_INODE 保持 doit**: 单条回复不需要 dump 协议，保留 `net_delayacct_one_reply()` 共用填充逻辑
- **防御性清零**: `.start` 入口处显式 `memset(cb->ctx, 0)`，避免依赖框架 zero-init 实现细节

### 2.2 用户态过滤协议（ISSUE-5/6）

- **复用现有 UAPI 属性**: 遵循 `inet_diag` 约定，用同一套属性 ID 同时作为请求过滤条件和响应输出字段，零 ABI 扩展风险
- **过滤在 `.dumpit` 中执行**: 通过 `genl_info_dump(cb)` 获取请求 info，在遍历 socket 时实时匹配；不存入 `cb->ctx` 是因为 ctx 仅剩 8 字节
- **6 维可选过滤**: proto/family/lport/rport/laddr/raddr，缺失属性视为通配符
- **地址比较按 socket family 区分**: IPv4 比较 4 字节 `__be32`，IPv6 比较 16 字节 `in6_addr`；过滤地址长度与 socket family 不匹配时跳过

### 2.3 端序处理（关键修复）

- **`sk->sk_num` 是 `__u16` host byte order**: 不需要 `ntohs()`，修复前错误翻转导致端口显示/过滤为字节翻转值
- **`sk->sk_dport` 是 `__be16` network byte order**: 需要 `ntohs()`，保持正确
- 此 bug 隐藏至 v5.0.0 才暴露，因为之前测试未检查具体端口号

## 六、系统性教训

### 6.1 内核字段端序必须核对类型定义

`sk->sk_num`（`__u16`, host order）和 `sk->sk_dport`（`__be16`, network order）端序不同，不能统一套用 `ntohs()`。建议形成 checklist：
- 修改网络端口/地址转换前，先确认字段类型是 `__u16` 还是 `__be16`
- 新增端口相关测试时，使用非对称端口号（如 21416）验证端序

### 6.2 测试断言应基于输出格式而非环境行为

v5.0.2 的 F3 问题说明：断言不能依赖当前环境（IPv6 dual-stack）的绑定行为。应基于工具实际输出格式设计断言，并考虑 IPv4/IPv6 两种格式。

### 6.3 第三方工具行为需要充分了解

iperf3 server 有两个易踩坑特性：
- 默认同时监听 TCP 和 UDP，同一端口不需要启动多个 server
- 单线程处理同一端口的多个 client，TCP client 会阻塞 UDP client 建立控制连接
- UDP 数据 socket 生命周期与 client 绑定，client 断开后 server 关闭该 socket

设计测试时必须把这些行为纳入考虑，不能假设 server 会同时处理多个独立 client。

### 6.4 Patch 作者身份和版权必须统一

UAPI 头文件早期使用占位版权 `h1y2g3l4y5`，与项目其他文件不一致。建议在创建文件时就统一作者/版权，避免后期 Review 作为合规问题提出。

## 七、下版本关注点

以下问题不阻塞 v5.0.0 闭环，但建议在下版本（v6.0.0）或后续维护中考虑：

1. **过滤属性的策略校验**: 当前 `.validate = GENL_DONT_VALIDATE_STRICT`，建议确认内核是否对 `LADDR/RADDR` 的 `NLA_POLICY_MIN_LEN` 执行校验，避免畸形属性进入过滤函数。
2. **IPv4-mapped IPv6 地址过滤语义**: `--laddr 127.0.0.1` 不会匹配 `local=[::ffff:127.0.0.1]:port` 的 socket。若用户反馈，应在 UAPI 文档中显式说明"过滤地址的 family 必须与 socket 实际 family 一致"。
3. **大 socket 集过滤性能**: 当前每个 socket 都通过 `genl_info_dump(cb)` 解引用 info。若未来支持数千 socket 的高频查询，可考虑把过滤条件缓存到 `cb->ctx` 之外（当前 ctx 已用 40/48 字节）。
4. **端口范围校验**: `--lport`/`--rport` 当前对非数字输入会静默转为 0，建议后续增加与 `--proto`/`--family` 类似的输入校验。
