### 架构决策

1. **Test 13 并发查询混合空 PID + busy PID**
   - 背景：原实现只查 PID 1，无法覆盖真实 per-socket 并发路径
   - 最终选择：4 个 worker 查 PID 1 + 4 个 worker 查 iperf3 server PID
   - 理由：兼顾 fast-path（空 fdtable）与 slow-path（per-socket spinlock/dumpit）并发安全验证

2. **路径覆盖使用独立辅助程序**
   - 背景：iperf3 无法触发 splice/zerocopy/corked/IPv6 特定路径
   - 最终选择：新增 `delayacct_path_test` 辅助程序，提供 splice-server / zerocopy-server / corked-udp-client / tcp-sender 子命令
   - 理由：对已插桩路径做专项回归，而不是在文档中标注未覆盖

3. **Test 20 zerocopy 用法修正**
   - 背景：最初以为 QEMU 内核不支持 `TCP_ZEROCOPY_RECEIVE`
   - 最终选择：改为 `mmap(cfd, ..., MAP_SHARED)`，处理 `recv_skip_hint`，发送端设置 `TCP_MAXSEG`
   - 理由：参照内核 selftest `tools/testing/selftests/net/tcp_mmap.c`，普通匿名 mmap 在设计上不合法

| 6 | zerocopy 匿名 mmap 返回 EINVAL | `find_tcp_vma()` 要求 `vma->vm_ops == &tcp_vm_ops` | 使用 `mmap(cfd, ..., MAP_SHARED)` | TASK-28 |

### 系统性教训

- **复杂内核 API 优先参考官方 selftest**：`TCP_ZEROCOPY_RECEIVE` 的用法细节在 `tools/testing/selftests/net/tcp_mmap.c` 中有完整示例，可避免从头试错。
- **EINVAL 不一定是配置缺失**：应先通读 API 入口的参数校验逻辑。
- **脚本缩进敏感操作需整体替换**：对多行带制表符的代码块，小范围 Edit 容易引入格式回归。
