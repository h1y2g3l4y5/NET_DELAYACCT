### 架构决策

1. **per-skb 配对验证：awk 关联数组子集检查**
   - 背景：需要验证 set(tx_end_skb) ⊆ set(tx_start_skb)
   - 备选方案：comm 命令 / grep -vxFf / awk 关联数组
   - 最终选择：awk 关联数组（POSIX 标准，QEMU guest 必定可用，NR==FNR 惯用法可靠）
   - 理由：busybox 环境兼容性

2. **ACK 容忍阈值：绝对下限 + 百分比双重保障**
   - 背景：纯 ACK/FIN 等控制包经过 tx_end 但不经过 tx_start，导致集合不匹配
   - 备选方案：严格 0 错配 / 纯百分比阈值 / 绝对下限 + 百分比
   - 最终选择：`max(25, tx_end_unique × 40%)`
   - 理由：KVM 下 mismatched 恒定 ~18 但 tx_end_unique 波动 50-70，纯百分比不稳定；绝对下限 25 确保不随分母波动

3. **helper 去重：仅提取 corked 逻辑，不重构 tcp-sender**
   - 背景：SCOPE 建议检查 tcp-sender 是否有可提取的公共逻辑
   - 最终选择：仅提取 corked_send_loop，不重构 tcp-sender
   - 理由：tcp-sender 用 send()（面向连接）+ 无 cork + TCP_MAXSEG，与 corked 的 sendto() + cork/uncork burst 本质不同

### 关键议题复盘

1. **议题 2.1.1（低）— trace ring buffer 溢出未检测**
   - 问题：直接从 trace 提取 skb 指针，未检查 ring buffer 是否溢出
   - 方案：在提取前检查 entries-in-buffer/entries-written 比率，溢出时输出 [warn]

3. **额外发现 — 阈值 30% 在 KVM 下不稳定**
   - 问题：CI run #130 失败，30% 阈值在 tx_end_unique=50 时降到 15 < mismatched=18

   - 教训：百分比阈值在分母波动大时不可靠，必须设绝对下限作为安全网

### 系统性教训

- **教训 1**：kprobe events 验证的是"函数被调用"而非"函数执行有效逻辑"。设计断言时必须结合函数内部守卫语义，否则会产生假阳性。
- **教训 2**：KVM/TCG 双环境下，计数/阈值类断言必须以 KVM 数据为基准设计——"本地 TCG 通过 ≠ CI KVM 通过"已三次验证（v6.2.0 done/fi、v6.3.0 ACK 占比、v6.3.0 tx_end_unique 波动）。
- **教训 3**：百分比阈值在分母波动大时不可靠。当分子恒定但分母波动时，必须设绝对下限作为安全网。
- **教训 4**：阈值稳定性分析应基于多次运行数据，而非单次 CI run。Reviewer 的阈值审查也应要求多次运行数据支撑。
