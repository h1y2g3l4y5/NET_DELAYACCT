### 关键议题复盘

1. **议题 2.1.1（高）— Test 24 kprobe `$arg2` 依赖 BTF 但内核未启用**
   - 问题：`$argN` 语法需要 CONFIG_DEBUG_INFO_BTF=y，项目内核未启用 → kprobe 注册失败被 `2>/dev/null` 静默吞掉 → Test 24 永远 SKIP。
   - 方案：改用 x86_64 寄存器语法 `skb=%si:u64`（arg2=RSI）。
   - 教训：kprobe 参数语法选择需确认内核 tracing 配置；echo 重定向 stderr 会掩盖注册失败，应显式检查 `kprobe_events` 内容。

2. **议题 2.2.1（高）— Test 23 场景 SKIP 导致整个测试 FAIL（语义退化）**
   - 问题：v6.2.0 将 `PASSED_SCENARIOS < TOTAL_SCENARIOS` 一律判为 `_fail`，与 v6.1.0 "环境缺失 → SKIP" 共识矛盾。
   - 方案：引入 `FAILED_SCENARIOS = TOTAL - PASSED - SKIPPED`，区分"场景跑不了"（SKIP）和"场景跑了但断言失败"（FAIL）。
   - 教训：修改已有断言行为时，必须检查是否与之前对话中达成的共识冲突。

3. **议题 2.3.1（高）— 全部代码变更未经本地测试验证**
   - 问题：TASK-33~37 编码完成后未运行本地测试就提交 Review，导致问题 2.1.1（BTF 缺失）这种"运行一次就能发现"的阻断性问题由 Reviewer 静态审查发现。
   - 方案：先修复 2.1.1，运行 `./local-test.sh --qemu-only`，确认 25/25 PASS 后再提交复审。
   - 教训：编码后必须立即运行本地测试，不能让 Reviewer 扮演"第一个测试者"。

4. **议题 2.2.2（中）— Test 24 名实不符**

   - 教训：测试的名称和描述必须与实际验证内容一致，不能名实不符。

5. **议题 2.1.2（中）— Test 24 残留调试输出**

## 五、TASK-38 CI 语法错误专题

### 根因

ci.yml 中 tc/iptables 打包代码从 `local-test.sh` 的函数式写法改写为内联式时引入笔误：`if [ "$bin" = "tc" ]` 块的闭合关键字误写为 `done`（应为 `fi`）。bash 在解析阶段即退出 (exit 2)，**整个脚本从未执行** —— 故 ERR trap 未触发、initramfs 未构建、QEMU 未启动、`/tmp/qemu.log` 不存在。

### 为什么 CI 失败而本地测试一直通过

`local-test.sh` 中等价代码正确使用 `fi`（第 268 行），故本地 `./local-test.sh --qemu-only` 一直 25/25 PASS，而 CI 始终 exit 2。**本地通过 ≠ CI 通过**——内联脚本与函数式脚本的结构差异（for 用 done、if 用 fi）是高危抄写点。

### 诊断方法论

1. **先看 exit code**：1 = 测试失败（有 [FAIL] 行），2 = 脚本/语法错误（bash 解析阶段退出）。
2. **再看 qemu.log 是否生成**：未生成 = 失败在 QEMU 启动前/initramfs 构建阶段。
3. **公开仓库可经 WebFetch 抓取 run 页面注解**（annotations）定位失败，无需 admin 权限下载日志。
4. **提取 ci.yml run 块用 `bash -n` 校验**：`python3 -c "import yaml..."` 提取 → `bash -n /tmp/step.sh`。

### 修复

- commit 9068ad3：测试计数 bug（`grep -c || echo 0` → `grep -Ec || true; ${VAR:-0}`）+ ERR trap 诊断 + 防御式 tc/iptables 打包
- commit 7d3ed90：done → fi（根因修复）

### 系统性教训

- **"本地通过 ≠ CI 通过"**：ci.yml 内联 bash 与 local-test.sh 函数式 bash 的结构差异（done/fi、for/if 嵌套）是高危抄写点。任何 ci.yml run 块修改后必须 `bash -n` 校验。
- **CI 失败诊断顺序**：先看 exit code (1=测试失败, 2=语法错误) + qemu.log 是否生成（未生成=失败在 QEMU 启动前）。
- **kprobe 参数语法**：优先用寄存器语法（`%si:u64`）而非 BTF 语法（`$arg2`），除非内核明确启用 BTF。
- **测试名实一致**：测试名称必须与实际验证内容一致；若实现降级，名称和描述必须同步更新。
- **场景级 SKIP/FAIL 区分**：环境缺失（SKIP）和功能缺陷（FAIL）是不同严重度事件，前者优雅降级，后者必须阻断。
